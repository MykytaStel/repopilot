# v0.22 E2 CLI Truth and UX Specification

Status: done

## Problem

Several existing CLI paths present technically valid data with misleading
meaning. An empty scan looks healthy, follow-up commands can silently change
visibility, disabled review gates look passed, cached execution time looks like
cache latency, missing review paths are diagnosed as a missing Git executable,
and `init` can create repository-owned files below the Git root.

## Outcome

RepoPilot tells the truth about what it assessed, preserves the user's analysis
intent in suggested commands, distinguishes disabled policy from a passing
gate, labels cached verification evidence accurately, diagnoses invalid paths
at the boundary, and initializes repository-owned files at the repository root.

## Contract

### Assessment status

- Every scan summary has a derived assessment status.
- `files_analyzed > 0` is `assessed`; `files_analyzed == 0` is `not-assessed`.
- An error diagnostic still produces `BLOCK`; otherwise a not-assessed scan
  renders `Decision: NOT ASSESSED` and does not claim numeric health,
  maintainability, or risk in human output.
- JSON and baseline JSON include `assessment_status` with the stable values
  `assessed` or `not-assessed`. Existing numeric score fields remain for
  backward compatibility and must be interpreted through this status.
- The additive field advances scan report schema `0.25` to `0.26`; `0.25`
  remains accepted by compatibility readers.
- A not-assessed scan remains a successful command unless an existing error or
  gate contract requires a non-zero exit.

### Path and initialization behavior

- `review` rejects a missing target before invoking Git and reports that the
  target path does not exist. A missing Git executable retains its existing
  distinct diagnosis.
- When `init` runs inside a Git worktree, its default config, GitHub Action, and
  MCP bootstrap outputs are rooted at the Git top level.
- Outside Git, `init` retains current-directory behavior.
- An explicit absolute `--path` is used as-is. An explicit relative `--path`
  remains relative to the invocation directory; only the default config path is
  Git-rooted.

### Human guidance

- A Markdown follow-up command emitted after strict visibility includes
  `--profile strict`; `--include-maintainability` may normalize to that
  equivalent stable profile flag.
- Review signal policy `none` renders `Review gate: disabled` in console and
  Markdown. Enabled policies continue to render passed or failed with counts.
- Reused verification evidence renders its duration as the original execution
  duration, for example `cached; original run 1078 ms`. It must not imply that
  the cache lookup took 1078 ms.

## Compatibility

- No new top-level commands, network behavior, dependencies, or exit codes.
- Scan/review findings, ordering, gates, SARIF, and baseline identity remain
  unchanged.
- JSON changes are additive; existing fields are retained.
- MCP receives the additive scan JSON field through the shared report model.
  Its disk-cache generation is advanced so a pre-0.26 cached report cannot
  hide the new status.

## Verification

- Real-binary tests cover empty console/JSON output, missing review paths,
  strict follow-up commands, disabled gates, and Git-root-aware init.
- Renderer tests cover executed versus cached verification timing copy.
- Existing JSON schema/golden fixtures are updated only for the additive field.
- The final tree passes formatting, Clippy, all tests, release-contract checks
  when applicable, and the P1 self-scan gate.
