# v0.22 B2.2b Changed-Scan API Contract Parity — Implementation Plan

> **Execution note:** implement this plan with RED/GREEN checkpoints in order. Do not commit,
> push, or open a PR until the user explicitly asks. Keep production files below RepoPilot's
> line and fan-out limits; split tests and adapters before they exceed those limits.

**Goal:** Make `review` and `scan --changed` report the same conservatively proven
TypeScript/JavaScript removed-export defect through one shared detector and stable rule ID,
while changed scan reuses B2.2a symbol facts instead of reparsing current files.

**Architecture:** Move the fact-level detector and exact occurrence record into
`analysis::api_contract`. Keep Git/source selection and cache policy in thin review and changed-scan
adapters. The shared detector accepts supported modified exporter paths, the current coupling graph,
a revision-matched file inventory, and a lazy fact provider. The scan adapter projects canonical
occurrences into ordinary findings before enrichment, so configuration, baselines, output, MCP,
risk, and CI gates continue through existing infrastructure.

**Tech stack:** Rust 2024, tree-sitter-backed `JavaScriptSymbolFacts`, Git revision sources,
changed-scan/context caches, serde JSON integration tests, existing rule registry and finding pipeline.

**Authoritative spec:**
`docs/engineering/v0.22-b2.2b-changed-scan-api-contract-spec.md`

## Non-negotiable contracts

- Keep the public detector ID exactly `behavioral.removed-export-still-imported` in both products.
- Do not add a command, flag, MCP tool, public finding field, or finding category.
- Do not read current source or parse current files inside the shared detector or scan adapter.
- Use changed `ParsedArtifact` facts first, then the compatible parsed cache keyed by current hash and
  language; a miss suppresses the claim.
- Parse only authoritative pre-change exporter sources, once per exporter/provider pass.
- Treat the graph as a candidate index; require resolver equality against the current inventory.
- Keep review JSON, target path, IDs, gating, feedback, impact, and MCP replay unchanged.
- Keep full scans silent because they have no authoritative pre-change contract.
- Do not bump parsed-cache schema/version; bump the repository-context cache schema for the
  path-to-content-hash lookup key discovered during implementation.
- Run focused tests during implementation and one full gate only at handoff.

### Step 3.2 — Add the scan-native fact provider

Define a private context/provider in `changed/api_contract.rs`. It receives narrow references instead
of the whole engine/stage objects:

- repository root and selected `DiffTarget` (`WorkingTree` or `Refs { base, head: "HEAD" }`);
- supported modified `ChangedFile` entries;
- current changed `ParsedArtifact` map;
- current repository-context path-to-content-hash map and file language;
- mutable `ParsedFactsCache`;
- current `ScanFacts.files` inventory;
- current relative `CouplingGraph`.

Current lookup order is mandatory:

1. normalized changed artifact's `javascript_symbols`;
2. current repository-context hash/language into `ParsedFactsCache::lookup`;
3. `None`, with no source read or parse fallback.

Pre-change lookup uses `pre_change_source` with the selected target, extracts facts once, and
memoizes by exporter path. Add only the smallest parsed-cache accessor needed to retrieve cloned
symbol facts; do not expose entire cache entries outside scan internals.

Persist the deterministic content hash on each repository-context node and bump that cache schema so
old entries without the lookup key are invalidated. The context cache owns path/revision identity;
the parsed cache remains the only owner of symbol payloads. Build the current inventory once from
`repo_stage.repo_context.files`; normalize it exactly as the graph/resolver expects. Missing graph
candidates, inventory, source, artifact, path/hash key, or cache facts return no occurrence.
