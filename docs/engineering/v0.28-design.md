## Architecture by slice

### RP28-01 — Cross-file test integrity

The Python and Go adapters extend the existing JS/TS one-hop assertion-helper
analysis. Changed-helper discovery and test-level accounting remain shared;
Python recognizes unique module-scope named imports and excludes shadowed
callers. Go matches direct unqualified calls within the same directory and
package. Findings retain the unchanged test occurrence and the called helper's
declaration line.

Remaining evidence and verification tasks:

1. Add real Python and Go motivating changes and confirm each miss on 0.27;
   current temporary-repository tests establish fixture behavior only.
2. Expand controls for duplicate helpers, coordinated updates, re-exports, and
   ambiguous import targets. A moved or renamed test is treated as changed and
   excluded from the unchanged-test attribution pass.
3. Changed-review, CLI, and MCP parity fixtures now cover Python and Go; retain
   cold/warm-cache and reviewed-precision evidence as open work.

Implementation: `src/review/signals/integrity/cross_file.rs` and its
`cross_file/{adapters,imports,tests}.rs` modules; shared accounting remains in
`src/review/signals/integrity/accounting.rs`.

### RP28-02 — One-boundary local taint flow

The current `src/review/signals/taint/flow.rs` is explicitly intra-procedural:
it seeds one scope, checks its sinks, then analyzes nested scopes independently.
The bounded helper-summary layer for JS/TS, Python, and Go maps a function
parameter to a supported sink or a simple identity return. It applies only when
a call resolves to one same-file helper. Arguments bind to parameters by
position or by Python keyword. The analysis evaluates state at each sink and
attributes a finding to the call only when the call contributes to that flow.
Existing source, sanitizer, sink, and changed-line evidence tables remain the
language contract. Unsupported helper
return transformations keep their incoming taint; grouped Go parameters retain
argument positions. Shell argv handling inspects all options for command mode,
including PowerShell encoded commands. Proven identity returns propagate through
caller aliases in statement order, and a changed call can surface an unchanged
helper sink while preserving the sink location and changed call evidence.

Remaining evidence and verification tasks:

1. Validate the candidate against real request/argv-to-helper examples; current
   unit fixtures do not establish production recall.
2. Safe controls cover sanitizers, argument vectors, unknown calls, clean
   overwrites, recursion, duplicate targets, and earlier sinks; broaden these
   cases against real request/argv-to-helper examples.
3. Changed-line semantics, real-project quality, and full output parity on
   changed/cold/warm cache paths remain open.

Implementation: `src/review/signals/taint/flow.rs`, the bounded helper-summary
modules under `src/review/signals/taint/helper_summary/`, and process argument
classification in `src/languages/{javascript,python,go}/review.rs`.

### RP28-03 — Local C/C++ include impact

C, C++, and header files now have parser-free import-only frontends for direct
quoted `#include` directives. The resolver accepts only unique targets relative
to the includer or repository root and keeps unresolved search candidates
inside the repository. Compiler flags, macro includes, system headers, and
conditional compilation remain unresolved. The lexer recognizes conditional
directives across line splices and comments, and ignores include-like text in
raw string literals. The generated support page comes from the registered
frontend capabilities.

Remaining evidence and verification tasks:

1. Path tests cover spaces and non-ASCII names, nested local targets,
   system/macro syntax, ambiguity, cycles, escapes, and conditional branches.
2. Changed-file impact tests now assert the route through a nested include and
   label the result as a static graph path.
3. Generated support docs, semantic report compatibility, and performance
   parity remain release evidence tasks.

Implementation: `src/languages/c_family/`,
`src/graph/resolver/c_family.rs`, `src/graph/resolution_stats.rs`, and the
language-support and coupling-graph regression tests.

### RP28-04 — Rust public enum-variant contracts

Extend the Rust API-contract path that already recognizes removed public
functions, function arity changes, and public struct-field removal. Match a
removed public variant to a surviving, uniquely resolved `Enum::Variant`
constructor or match pattern in local source. Prove each file-backed module
hop, exclude shadowed type names, and abstain when a same-named inherent item
can replace the variant. Preserve declaration and caller spans. Use the existing
`removed-export` proof delta with a distinct review signal for the Rust evidence.

Remaining evidence and verification tasks:

1. Fixture coverage includes unit, tuple, and struct variants; compare the
   detector against real local API changes before making quality claims.
2. Expand abstention controls for macros, re-exports, ambiguous modules, and
   same-name enums.
3. CLI/MCP parity, explanation, proof obligations, declaration/caller evidence,
   and the generated rules reference are covered locally; real-project and
   downstream-boundary evidence remain open.

Implementation: `src/analysis/api_contract/rust_enum.rs`, Rust symbol facts,
changed-finding and tiered-signal mappings, proof obligations, and the
behavioral rule registry.
