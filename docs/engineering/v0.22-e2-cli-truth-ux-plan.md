# v0.22 E2 CLI Truth and UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every affected CLI surface accurately describe assessment scope, policy state, cached evidence, paths, and generated-file ownership.

**Architecture:** Derive assessment state once from `ScanSummary` and project it through shared report/render boundaries. Keep path validation at the review boundary, Git-root discovery at init admission, and timing wording in the verification model/render seam so analysis behavior is unchanged.

**Tech Stack:** Rust 2024, clap, Serde JSON, existing console/Markdown/HTML renderers and integration-test harness.

**Spec:** `docs/engineering/v0.22-e2-cli-truth-ux-spec.md`

## Global Constraints

- No new dependencies, top-level commands, network behavior, or exit codes.
- JSON additions are backward-compatible and deterministic.
- Preserve finding, gate, baseline, SARIF, and MCP analysis semantics.
- Use failing behavior tests before production changes.
- Do not commit, push, or open a PR until explicitly requested.
