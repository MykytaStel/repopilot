# v0.25 Rust public-function contracts

This contract note covers two bounded Rust breaking changes: a removed
top-level `pub fn` that a current local caller still uses, and a changed
parameter count whose proven direct caller still supplies the previous number
of arguments. It does not compare the Rust API surface generally.

## Supported proof

The caller must declare the file-backed child module, such as `mod api;`, and
then import the function (`api::load` or `self::api::load`, including `as`
aliases) or call it directly (`api::load()` / `self::api::load()`). `crate::`
paths are accepted only from `src/lib.rs` or `src/main.rs` when that root
declares the same child. The ordinary resolver must identify exactly one
existing `api.rs` or `api/mod.rs` candidate.

Review and `scan --changed` retain caller and exporter locations and exact
occurrence evidence in their existing CLI/MCP adapters and cold/warm changed
caches. Full scans do not have the historical source needed to prove removal.

## Public-function arity proof

The exporter must retain one top-level, non-generic `pub fn` with a unique name
in both revisions, and its parameter count must change. A surviving caller must
contain a direct module-qualified call such as `api::load(value)` or
`self::api::load(value)` through the same file-backed child-module proof above.
The current call's argument count must equal the old parameter count and differ
from the new count. The finding retains the caller path/span and exporter path.
Changed scans cache these Rust facts and invalidate older parsed-fact entries.

Same-arity type changes, bare calls through imported aliases, generic and
variadic functions, methods, and calls whose previous argument count did not
match the old signature are outside this slice. A coordinated call update is a
safe control.

## Abstentions and evidence limits

The detector abstains on arbitrary sibling callers and deeper crate hierarchies,
`super::` paths, grouped or glob imports, module aliases and re-exports,
attributes (including `cfg` and `path`), macros, inline modules, malformed
syntax, foreign declarations, and nested imports/modules. Associated methods
and generic-function call sites are outside this slice. Bare qualified calls
are excluded when a lexical block declares a matching struct, enum, union,
type alias, or trait; explicit `self::`/`crate::` paths and top-level imports
retain their module proof.

A preserved public name or a coordinated caller edit/removal does not establish
a break. Private/`pub(crate)` replacements, same-name items, visibility or
kind changes, parameter type changes that keep the same count, fields, traits,
and module/file renames are follow-up work. Current evidence is fixture-based;
it does not establish real-repository precision or recall.
