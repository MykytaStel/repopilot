# v0.25 Rust public-function removal

This slice detects one bounded breaking change: a removed top-level `pub fn`
that a current, direct local caller still uses. It does not compare the Rust
API surface generally.

## Supported proof

The caller must declare the file-backed child module, such as `mod api;`, and
then import the function (`api::load` or `self::api::load`, including `as`
aliases) or call it directly (`api::load()` / `self::api::load()`). `crate::`
paths are accepted only from `src/lib.rs` or `src/main.rs` when that root
declares the same child. The ordinary resolver must identify exactly one
existing `api.rs` or `api/mod.rs` candidate.

Review and `scan --changed` retain caller and exporter locations and exact
occurrence evidence in their existing CLI/MCP adapters and cold/warm changed
caches. Full scans do not have the historical source needed to prove removal.

## Abstentions and evidence limits

The detector abstains on arbitrary sibling callers and deeper crate hierarchies,
`super::` paths, grouped or glob imports, module aliases and re-exports,
attributes (including `cfg` and `path`), macros, inline modules, malformed
syntax, foreign declarations, and nested imports/modules. Associated methods
and generic-function call sites are outside this slice. Bare qualified calls
are excluded when a lexical block declares a matching struct, enum, union,
type alias, or trait; explicit `self::`/`crate::` paths and top-level imports
retain their module proof.

A preserved public name or a coordinated caller edit/removal does not establish
a break. Private/`pub(crate)` replacements, same-name items, visibility or
kind changes, signatures, fields, types, traits, and module/file renames are
follow-up work. Current evidence is fixture-based; it does not establish
real-repository precision or recall.
