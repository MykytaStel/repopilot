# RepoPilot 0.23 Phase C — Intent Drift and Critical Paths

Status: approved; implementation in progress

## Context

The Phase A and Phase B proof model is now on `origin/main`, including typed
contract deltas, bounded impact paths, verification obligations, and the
canonical `ChangeProof`. Phase C adds a bounded declaration of expected impact
without introducing a task tracker, a second verdict engine, free-form policy,
or implicit command execution.

## Problem

RepoPilot can explain observed contract and consumer impact, but it cannot
compare that evidence with the change author’s intended boundary. A repository
also needs named, repository-owned critical areas whose intersections are
visible even when the author did not supply an intent contract.

## Outcome

`review` can optionally evaluate a validated intent contract against the same
changed files, bounded consumers, contract families, and configured critical
paths that feed `ChangeProof`. The result is deterministic, additive, and
explainable in JSON and MCP output. Missing intent is explicitly reported as
`not-supplied`, never as a finding or a penalty.

## Contract

### Intent input

The CLI accepts `review --intent <path>` where the file is a repository-rooted,
bounded TOML document. MCP accepts the same object inline and may use an
explicit repository-rooted `intent_path`. The input has no command field and
cannot cause a process spawn.

```toml
version = 1
summary = "Update authentication token validation"
paths = ["src/auth/**", "tests/auth/**"]
contract_families = ["security-boundary", "public-symbol"]
critical_paths = ["authentication"]
verification = ["unit"]
```

All lists are bounded and sorted/deduplicated for evaluation. Paths are
repository-relative forward-slash globs; absolute paths, traversal, malformed
globs, oversized files, unknown contract families, unknown critical-path names,
and unknown verification IDs are rejected before analysis or verification.
`summary` is bounded display metadata only and is never interpreted.

### Repository critical paths

`repopilot.toml` may declare named paths:

```toml
[[review.critical_paths]]
name = "authentication"
paths = ["src/auth/**", "src/middleware/auth.rs"]
```

Critical paths are repository policy. They do not suppress findings and do not
change a verdict by themselves. Their intersections with changed and impacted
paths are carried as evidence.

### Drift semantics

Actual scope is the union of changed files and bounded direct/transitive
consumers. Drift is reported when a supplied intent declares a non-empty path
scope and actual scope contains an unmatched path, a detected contract family
is absent from the declared family set, a configured critical area is touched
but absent from the declaration, or an expected verification ID was not
selected. Contract-family and critical-path comparisons use the canonical
ChangeProof inputs; they do not re-run analysis.

The proof contains one of `not-supplied`, `within-scope`, or `drifted`. Drift
adds a canonical `intent-drift` proof reason and therefore keeps the overall
proof at `REVIEW`; it never hides findings, signals, or failed verification.
`not-supplied` is informational and does not prevent `VERIFIED` when the other
proof requirements are satisfied.

### Security and determinism

- Intent/config paths are root-confined and validated before analysis.
- Input and each field/list have explicit size limits.
- No network, clock, randomness, LLM, shell text, or implicit verification is
  involved.
- Identical intent and workspace revision produce byte-stable evidence.
- Repository-controlled summary text and paths are escaped by existing output
  renderers.

### Compatibility

The existing CLI commands, flags, finding identity, readiness, gates, and
ChangeProof verdict labels remain compatible. The new CLI flag, config section,
MCP properties, and `change_proof.intent_drift` field are additive. Private
intent files can live under `.repopilot/` and remain local through the existing
ignore policy; no intent source is copied into GitHub artifacts.

## Definition of done

- Core model tests cover not-supplied, within-scope, drift, deterministic
  ordering, malformed input, unknown IDs, traversal, and size limits.
- Changed and full reviews use the same evaluation and canonical ChangeProof.
- CLI and MCP validate intent before analysis; no verification command can be
  supplied through intent.
- JSON and existing human projections disclose intent status without changing
  legacy fields unexpectedly.
- Configuration and CLI documentation describe the local/private boundary.
- Focused tests, full Rust tests, formatting, clippy, self-scan, and the
  release-contract gate pass before PR handoff.
