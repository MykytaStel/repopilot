# v0.23 Phase 0B2 Compatibility Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` or `superpowers:executing-plans` to
> implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Replace assumed report compatibility with version-provenanced released
producer/reader evidence and make incompatible history visible without changing
comparison semantics.

**Architecture:** Immutable JSON fixtures and a manifest capture external
release evidence. Rust integration tests exercise current readers and baseline
behavior offline. A narrow history diagnostic exposes an existing unavailable
comparison; it does not create a risk delta or alter exit policy.

**Tech stack:** Rust integration tests, serde JSON, SHA-256, GitHub release
assets, exact crates.io package versions, Markdown evidence.

**Spec:** [Phase 0 specification, 0B2](v0.23-phase-0-spec.md#0b2--released-compatibility-evidence-pr-2).

## Global Constraints

- Runtime scanning remains local-only and deterministic.
- No top-level command, MCP tool, package version, or report schema changes.
- External downloads are maintainer evidence capture, never a normal test or
  product-analysis dependency.
- A rejected old reader is explicit unsupported behavior, not a defect by
  itself. Missing released tags remain synthetic evidence.
- Incompatible history never produces new/resolved classifications.
