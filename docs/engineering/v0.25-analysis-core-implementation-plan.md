# v0.25 Analysis Core Implementation Plan

> For agentic workers: use superpowers:subagent-driven-development to execute
> these tasks sequentially, with task reviews and a final branch review.

**Goal:** keep long-lived review results fresh and extend direct API/SQL contracts
without overstating unsupported language or measurement coverage.

**Architecture:** reuse the existing resolver, syntax symbol facts, contract
signals and intra-procedural taint pipeline. Add bounded facts at those boundaries,
then consume them through the existing CLI/MCP adapters. Index JVM candidates
only after a reproducible scaling measurement.

**Tech stack:** Rust 2024, tree-sitter language frontends, existing Rust test
harnesses and Node/Python engineering scripts.

**Spec:** [approved release scope](../roadmap/v0.25.md). This plan implements
RP25-T01 through RP25-T05; U01/E01/E02 require external observations and remain
separate. Authorization: user requested all technical work and a draft PR.

## Global Constraints

- Analysis is local and deterministic: no network, clock-dependent output or
  randomness in analysis paths. No new top-level command.
- Keep new source files below about 300 lines and functions below about 50;
  split touched responsibilities into focused modules when necessary.
- Preserve strict-profile recall and occurrence identity; finding IDs are not
  sufficient deduplication keys.
- New behavior needs unsafe and safe controls. Begin each behavior change with
  a failing regression. Compare complete normalized semantic evidence on
  equivalent scopes, excluding root paths, timing, handles and cache telemetry.
- CLI and MCP must preserve the same retained signal and occurrence evidence.
  Full/changed/cache projections retain intentional scope differences.
- Update user-facing documentation, Unreleased changelog and each ledger row.
  Synthetic fixtures prove bounded behavior, not real-world precision/recall.
- No version bump, tag, release publication, catalog acceptance claim or merge.

## Review Focus

- Stale alias edges after config-only changes in one process.
- False API breaks from uncertain forwarding, parser failures or coordinated edits.
- Rust paths that claim certainty despite macro/cfg/re-export ambiguity.
- C# flows that confuse command receivers or ignore a clean overwrite.
- JVM indexing that changes ambiguous candidates, order or evidence.

   Test cold/warm and a fresh process against identical effective inputs.
5. Run focused resolver, scan-cache and MCP freshness tests, fmt and diff check.
   Record RED/GREEN commands/results and exact limitations; update RP25-T01,
   relevant docs/Unreleased, self-review, then commit this task.

## Task 5: JVM graph scaling (RP25-T05)

**Ownership:** src/graph/resolver/jvm.rs and focused resolver index modules;
tests/perf_matrix.rs or a focused scaling harness; scripts/check-review-performance.js
only if needed; relevant docs/changelog and RP25-T05 row.

1. Add a deterministic many-file/import workload with both resolved and
   unresolved imports and ambiguous suffix matches. Measure the original
   implementation before optimization: pinned size, environment, elapsed time
   and peak memory. Store raw measurements in task report, concise evidence in docs.
2. If justified, index JVM candidates once per graph rather than scanning the
   full inventory per import. Preserve language/path matching and ambiguity.
3. Assert complete deterministic edges/evidence before/after and cold/warm;
   include duplicate/ambiguous names and missing imports. Keep a regression
   budget with enough margin for CI variability; do not add a flaky stopwatch test.
4. Run focused graph/performance tests and existing performance gates. Existing
   budgets: 123-file review median <= 2,100 ms; 20-file integrity <= 1,000 ms;
   integrity share <= 10%. Record denominator and measured limits.
5. Update RP25-T05/Unreleased/docs, self-review and commit this task. If the
   baseline does not justify optimization, report that result honestly and
   still deliver the reproducible workload and semantic controls.
