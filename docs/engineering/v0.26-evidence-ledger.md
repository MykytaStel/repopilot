## Release-prep optimization follow-up

The first matcher-only fast path did not resolve the hosted integrity budget:
head `ee861c04` measured 10.145 ms integrity time over an 86.43 ms review
(11.74%). A tagged phase trace then attributed 8.9–10.5 ms to cross-file helper
analysis. That pass built the Git inventory before checking whether changed
helpers contained assertion evidence. The follow-up now performs the helper
check first and skips inventory creation if no assertion helper changed.
It now also checks resolved assertion counts before extracting export
symbols, skipping both when no assertion evidence changed.

On the same host and 20-file fixture, the isolated integrity median fell from
13.532 ms to 4.181 ms (-69.1%). The 10% share limit is unchanged. The final
local full gate passed at 4.13/173.57 ms (2.38% share), with a 930.48 ms
123-file median and 0.323 changed/full ratio. Two hosted CI runs on the same
source passed the unchanged 10% integrity-share limit: 8.22% (`82140d8d`) and
8.82% (`ccd418bb`, documentation-only follow-up). The latest run measured
9.659/109.52 ms integrity review and a 930.03 ms 123-file median.

The manual full release gate on merged `main`, run `41456308537`, later failed
only at the integrity-share check: 9.094/84.85 ms (10.72%; unchanged limit
10%). This prompted the grammar-index cache recorded under RP26-05. The
follow-up branch's paired fixture improved 5.267 to 4.380 ms (-16.8%), and its
full local release gate passed with a 4.933/251.96 ms integrity review
(1.96%), 1,114.65 ms 123-file median, and 0.329 changed/full ratio. Warm
480/1,000-file scans measured 314.18/651.64 ms; self-review had 42 signals
with no quality failures and self-scan had no findings or contract violations.
A fresh hosted full release gate is pending.
