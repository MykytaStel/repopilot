# RepoPilot 0.27.0: language analysis expansion and review improvements

## Problem

RepoPilot advertises language-aware analysis for eight frontends, but several
important behaviors are bounded or absent: resolver gaps hide broken local
imports, Rust public API checks cover only selected function contracts, C# SQL
flow abstains on aliases and branches, and Java/Kotlin source graphs omit
same-package references. Users need useful findings on real changes in these
languages without turning unresolved semantics into false certainty.

## Outcome

The 0.27 release extends analysis across Rust, JS/TS, Python, Go, C#, Java and
Kotlin with bounded, evidence-backed behavior. Review output helps users locate
the affected declaration/use, understand coverage and limitations, choose checks
to run, and recover from incomplete analysis. Existing CLI, reports, MCP and
agent integrations remain coherent and local.

## Scope

### In scope
- Extend import resolution and missing-local-import evidence for bounded local
  forms in JS/TS, Python and Go; do not claim resolution support already
  implemented as new behavior.
- Extend Rust public API change detection beyond removed free functions to at
  least one reproduced public struct-field contract.
- Improve C# SQL taint through local aliases and a bounded branch merge when
  safety can be established.
- Model Java/Kotlin same-package type references sufficiently for graph impact.
- Add a review check planner, CLI explanation path, honest coverage detail,
  resilient verification recovery, comparison/impact improvements where
  compatible with current APIs.
- Fix only reproduced review false positives, preserving safe controls.
- Update report/cache contracts when necessary and migrate version metadata to
  0.27.0 after behavior is ready.

### Out of scope
- Compiler, type-checker, runtime-reachability, whole-language or general
  interprocedural claims.
- Network access or dependency downloads during analysis.
- Automatic execution of suggested checks or persistent MCP consent.
- Removing findings solely to reduce counts.

## Constraints

Preserve deterministic local analysis, bounded runtime/memory, exact occurrence
identity, current schema compatibility or explicit schema migration, MCP
per-check consent, cache freshness, safe abstention on ambiguity, and the
repository's release gates. Keep modules focused and add meaningful positive,
negative and safe-control tests for new behavior.

## Design

Implement narrow slices from `docs/engineering/v0.27-audit-draft.md`. First
confirm each candidate is absent or incomplete in `origin/main`; the existing
TypeScript resolver already handles extensionless relative imports and the
Python resolver already handles absolute modules, so extend missing-import
proof and edge cases instead of duplicating resolution. Implement and measure
independently. Preferred first slices: explicit Go workspace/local-replace
resolution, Rust field contract evidence, C# receiver aliases, and JVM
same-package references. Then integrate guided review and coverage output.

## Verification
- Focused unsafe/safe regression cases for every changed language behavior.
- Full/changed scan, cold/warm cache and CLI/MCP parity where those paths use
  the changed facts.
- Formatting, Clippy, full tests, zoo expectations, performance and platform
  gates as applicable before handoff.
- `python3 scripts/release-contract.py check` and `bash scripts/verify-release.sh`
  before release; verify public channels after publication.

## Open Questions
- Synthetic unsafe/safe cases validate the shipped bounded syntax; independent
  real-repository precision and recall measurements remain open.
- The public schema change is limited to impact-route data in schema 0.27;
  parsed-facts cache schema and analysis identity were bumped for internal facts.
- No compatible client was available for live MCP elicitation observation;
  automated protocol tests do not substitute for client evidence.
