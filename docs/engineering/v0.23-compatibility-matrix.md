# v0.23 Report Compatibility Matrix

Status: verified for the directions and evidence levels below on 2026-09-02.

This matrix replaces a broad "backward compatible" claim with directional
results. `Supported` means the exact producer/reader pair was exercised.
`Rejected` means the reader fails closed at its documented schema boundary.
`Synthetic` means a current-reader transition fixture has no matching release
tag. `Not applicable` means the surface does not ingest that artifact type.

Source under test: `abb1513868c51a68299f1e4af9e578774cd458f6` (merged PR
#403), package 0.22.0, scan report schema 0.26. Evidence manifest:
[`tests/fixtures/reports/releases/manifest.json`](../../tests/fixtures/reports/releases/manifest.json).

## Released Producer to Current Reader

The producer reports came from checksum-verified GitHub release assets for
macOS ARM64. Each committed raw report has its own SHA-256 in the manifest and
is deserialized by the current public Rust reader in the handoff test suite.

| Producer | Tag commit | Emitted schema | Current reader | Evidence |
|---|---|---:|---|---|
| 0.16.0 | `a6aa1b70` | 0.18 | Supported | released asset + raw fixture |
| 0.17.0 | `2680f298` | 0.19 | Supported | released asset + raw fixture |
| 0.19.0 | `b8d4617b` | 0.20 | Supported | released asset + raw fixture |
| 0.20.0 | `97cc6beb` | 0.23 | Supported | released asset + raw fixture |
| 0.21.0 | `f23f36a2` | 0.23 | Supported | released asset + raw fixture |
| 0.22.0 | `a000dc7c` | 0.26 | Supported | released asset + raw fixture |

Version 0.18.0 does not add a distinct producer schema over 0.17.0, so the
matrix omits that duplicate raw report. Versions 0.20.0 and 0.21.0 are both
retained even though both emit schema 0.23: they cover adjacent released
producer and reader boundaries. The manifest pins every included release,
not merely a hand-authored schema number.

The current reader also accepts schemas 0.16, 0.17, 0.21, 0.22, 0.24, and 0.25
through existing synthetic fixtures. No release tag uniquely emits those
schemas, so their status is `Synthetic`, not released-producer evidence.

## Released Reader to Schema 0.26

Exact crates.io packages call the public
`repopilot::api::report::parse_scan_summary_json` facade against the released
v0.22.0 schema-0.26 report. The committed probe lock and package checksums make
the result reproducible without putting network access in RepoPilot runtime.
An explicit compatibility test compiles and runs the locked probe rather than
trusting the manifest's outcome strings.

| Reader | Input | Result | Meaning |
|---|---:|---|---|
| 0.20.0 | 0.26 | Rejected | accepts through 0.23; explicit unsupported schema |
| 0.21.0 | 0.26 | Rejected | accepts through 0.23; explicit unsupported schema |
| 0.22.0 | 0.26 | Supported | exact released reader accepts the report |

The rejected rows are not regressions. Additive JSON fields do not override an
older reader's explicit version allowlist. Consumers must upgrade to a reader
that names the new schema.

## Reproduction and Limitations

The manifest records the exact `gh release download`, producer, and exact-crate
reader commands. Run the executable reader compatibility assertion with:

```bash
cargo test --test released_report_compatibility \
  exact_released_readers_match_recorded_schema_outcomes \
  -- --ignored --exact
```

- Producer execution is proven on macOS ARM64. Platform archive identity and
  installation remain release/distribution evidence, not inferred here.
- The checked-in reports contain one real, redacted secret-candidate finding;
  they do not prove compatibility for every future optional field combination.
- This matrix says nothing about unpublished future schema 0.27 or package
  0.23.0. Each new schema needs a new directional row before release.
- No network call occurs during scan, normal tests, or report parsing.
