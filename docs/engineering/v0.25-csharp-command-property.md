# C# command-property SQL flow (RP25-T04)

Review follows a local receiver's `CommandText` assignment through
`ExecuteReader`, `ExecuteNonQuery`, `ExecuteScalar` and their `Async` variants,
using the existing C# SQL sink family. Retained detail names the recognized
source line, property assignment line and execution line. The execution remains
the signal location; changing the source, property assignment or execution can
make the flow relevant to the diff. CLI, MCP review and signal explanation retain
the same detail and signal identity.

This is syntactic intraprocedural evidence, without semantic SqlCommand type
resolution. Only straight-line declarations and expression statements in a
function's immediate block participate. Branches, loops, nested blocks and other
control statements invalidate state. Nested functions receive independent state.
Only a simple local receiver is supported; aliases, fields, dynamic receivers,
expression-bodied methods and interprocedural mutation are outside this proof.
Clean property overwrite and receiver reassignment invalidate prior state.
Compound property assignment preserves prior taint when the added value is clean.

Constant SQL with tainted bound parameter values remains silent. Adding Parameters
does not sanitize a tainted CommandText. Existing direct SQL argument detection
continues independently. State is computed from current review source and is not
persisted: private parsed/analysis cache schemas and signatures remain unchanged.

Evidence is synthetic fixtures: the pinned unsafe exclusion, six execution
methods, compound assignments, overwrite/reassignment/unrelated/no-execution,
parameterized SQL, branch/scope controls, assignment-only dirty diff, CLI/MCP
parity and retained explanation replay. No zoo precision claim is made.
