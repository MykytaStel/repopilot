# JVM inventory indexing evidence

RP25-T05 builds a lazy filename index once per immutable graph inventory.
Full coupling graphs, graph v2 snapshots and context graph rebuilds/patches use
it. Non-JVM imports retain their existing resolver, and no public format or
command changes. Java still resolves Java only; Kotlin resolves Kotlin/Java.
Package-tail boundaries, member stripping, production-over-test preference and
ambiguous production variants retain their existing behavior.

## Reproduce the bounded measurement

```sh
rustc --edition=2024 -O scripts/performance/jvm-scaling.rs -o target/jvm-scaling
/usr/bin/time -l target/jvm-scaling 3000 scan
/usr/bin/time -l target/jvm-scaling 3000 indexed
```

Use `/usr/bin/time -v` on Linux. Run the executable after compilation settles;
concurrent builds materially distorted intermediate measurements. Repeat each
algorithm three times. The `scan` mode invokes the original inventory-scanning
resolver retained verbatim, with the same input generator and result checks as
`indexed`. This is a standalone optimized resolver workload, not a Cargo release
CLI, parser, filesystem scan, review, MCP or zoo benchmark.

Workload `sequential-v1`: 3,002 absolute normalized Kotlin paths across 64 module
prefixes, 9,001 imports: 3,000 direct types, 3,000 companion-member imports,
3,000 missing third-party types and one ambiguous type with two production
variants. All 6,000 resolved and 3,001 unresolved outcomes are checked individually.
There is no random generator seed; ordinary HashSet iteration can vary, while
all expected results stay identical. The harness uses identity normalization for
these already normalized paths. Timing excludes result assertions; whole-process
peak RSS includes inventory construction and both result vectors. Cold means
first lookup pass after inventory/index construction, warm repeats the same
inventory; neither means a persisted RepoPilot cache hit.

(`4a4ef493e`, aarch64-apple-darwin), standalone `rustc -O`:

The measured scanning cost justifies pruning unrelated filenames. These results
establish only this workload on this host. Buckets with many identical filenames
still require checking all candidates; no universal constant-time or whole-review
speedup is claimed. Raw trial time/RSS/environment evidence is retained in the
ignored task-5 report and adjacent logs.

## Semantic checks and remaining gate

The JVM differential test checks complete outcomes against the original scanner
for Java/Kotlin extension sets, member imports, missing imports, boundary traps,
test-source preference, ambiguous variants, insertion order and repeated index
use. The graph regression checks complete sorted edges and unresolved evidence
through reversed input/warm rebuilds, graph v2 equality, nonempty deferred edges,
and a serialized context patched after deleting an ambiguous candidate. Existing
context cache and changed-graph tests also run.

Performance regression budgets remain the existing independent review gates:
123-file review median <= 2,100 ms; 20-file integrity <= 1,000 ms and integrity
share <= 10%. No host-dependent stopwatch assertion was added to Rust tests.
The whole-branch handoff runs those gates and records their denominator separately;
this direct JVM measurement does not establish that they passed.
