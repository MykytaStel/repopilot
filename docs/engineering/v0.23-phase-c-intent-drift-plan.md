# Phase C Intent Drift — Implementation Plan

## 1. Contract-first tests

- Add unit tests for bounded intent parsing, path normalization, family/name
  validation, duplicate ordering, traversal, malformed glob, and size errors.
- Add evaluator tests for not-supplied, within-scope, unexpected paths,
  unexpected families, critical-path drift, missing selected verification, and
  deterministic output.
- Run focused tests and observe the expected RED failures before production
  implementation.

## 2. Typed configuration and input boundary

- Add repository critical-path configuration under `[review]`.
- Add a reusable intent contract model and root-confined TOML/JSON loaders.
- Keep private intent documents outside tracked artifacts unless the user
  deliberately commits them; enforce limits before analysis.

## 3. Canonical review integration

- Evaluate intent from changed files, bounded impact paths, canonical contract
  deltas, and selected verification IDs.
- Store the typed assessment on `ReviewReport` and extend `ChangeProof` through
  the existing proof derivation path.
- Add one drift reason only for actual drift; keep absence informational.

## 4. Product surfaces

- Add `review --intent` and config precedence without adding a command.
- Add inline/path intent input to `repopilot_review_change` with schema and
  pre-analysis validation.
- Project status and bounded evidence through JSON and existing console,
  Markdown, HTML, SARIF, and stored MCP ChangeProof views.

## 5. Documentation and release evidence

- Document critical paths, intent format, limits, private-file handling, and
  the no-execution boundary.
- Add parity/security fixtures for changed/full and CLI/MCP paths.
- Run focused tests, then the complete repository handoff gate. Do not bump or
  publish the version in this PR.
