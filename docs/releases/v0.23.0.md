---
title: Change Proof — one bounded verdict for every review
description: RepoPilot 0.23 turns review into one Change Proof — a single verdict with its reasons, typed contract changes linked to their local consumers, proof obligations satisfied only by explicitly selected checks, and one next action — shared across every output.
---

## Highlights

- **One verdict per review.** The first screen is now `Decision: REVIEW (Change Proof: REVIEW)`, its reasons, the evidence scope, and one next action. `VERIFIED` requires a non-empty assessed scope and configured checks selected with `--verify` that pass; static analysis alone never awards it. Provenance, legacy merge readiness, ownership, and location details move to `--detail full`. The same canonical record drives console, Markdown, JSON, SARIF, the local HTML Change Map, MCP, and the GitHub Action Proof Card.
- **Typed contract changes.** Review now explains *what* changed in sensitive files instead of flagging them by path: Cargo and npm dependency additions, removals, version direction, source and feature changes; workflow trigger, permission, secret, action-reference, artifact, and deployment changes; runtime configuration key introduction, removal, and rename with proven local consumers; and changed access-control or request-trust boundaries linked to entrypoint candidates and related tests. Unclassified forms stay explicitly `limited` and keep the proof at `REVIEW`.
- **Intent drift and critical paths.** `review --intent <file>` compares the observed impact with an optional, bounded intent contract, and `[[review.critical_paths]]` marks domains such as authentication or billing. Drift is reported as a reason; it never suppresses findings or failed checks.
- **A path to `VERIFIED`.** `repopilot init --suggestions-output <file>` proposes stack-appropriate checks and critical paths, with the evidence behind each one, as a separate reviewable TOML file. Nothing is applied or executed automatically.
- **Honest coverage and provenance.** Changed tests, fixtures, and generated files are reported as policy-skipped instead of reducing coverage; reviews record the resolved base and head commits; and the generated rule scorecard reports Wilson intervals and a small-sample boundary instead of point estimates.

## Compatibility

RepoPilot 0.23 adds no top-level command. The following schema declarations
describe the tagged `v0.23.0` source, not future releases. The scan-reader input
range is inclusive.

| JSON surface | Schema version(s) |
|---|---|
| `scan` | `0.26` |
| `baseline-scan` | `0.26` |
| `review` | `0.26` |
| `receipt` | `6` |
| `scan-reader input` | `0.16–0.26` |

Review JSON gains the additive top-level `change_proof`, `decision`,
`evidence`, and `proof_receipt` objects, plus `coverage.policy_skipped_files`
and `provenance.base_commit`/`head_commit`. Existing `merge_readiness` values,
gates, and exit codes are unchanged. `change_proof.coverage.excluded_files` no
longer counts test, fixture, example, or generated files skipped by audit
policy; those appear in `policy_skipped_files`.

Review risk priority still includes review context: without a baseline, a
medium-severity finding on changed lines can be ranked `P0` in `review` while
`scan` ranks it `P1`. Treat review priority as urgency within the change, not
as severity. Calibration is planned for 0.24.

Quality evidence remains scoped to what was measured. This release makes no
broad precision, recall, or utility claim; see the
[reports and schemas](../reports.md) guide for the current contract.

## Upgrade

```bash
cargo install repopilot --version 0.23.0 --force
npm install -g repopilot@0.23.0
```
