---
title: Quiet fallbacks, broken callers of removed or changed APIs, and consent before MCP runs a check
description: RepoPilot 0.25.0 flags a changed empty catch or pass-only except as a fallback worth checking, follows more removed or changed APIs to callers that still use them, asks before an MCP client runs a configured check, and keeps TypeScript alias resolution fresh inside one MCP session.
---

## Highlights

- **Quiet fallbacks are surfaced in review.** A changed empty JS/TS `catch` or
  pass-only Python `except` around a call or optional import, in a function
  that can still return afterwards, raises
  `behavioral.quiet-fallback-introduced`. It is a maybe-tier, medium-confidence
  candidate: it points at the path to check and never gates. Tests, Promise
  `.catch`, explicit recovery, re-raise, and unchanged handlers stay silent.
- **More broken callers are caught.**
  - A removed direct JS/TS default export is reported when a surviving relative
    default import still uses it, with caller and exporter lines.
  - A removed Rust `pub fn` keeps its direct caller evidence through
    file-backed child modules declared in the caller.
  - A Rust top-level `pub fn` whose parameter count changed is reported when a
    proven direct module-qualified caller still passes the old number of
    arguments (`behavioral.rust-public-function-arity-changed`).
  - Coordinated caller updates, same-arity type changes, macros, `cfg`, and
    forwarding stay silent or are reported as limits.
- **C# SQL built through `CommandText` is followed.** A straight-line local
  `CommandText` assignment that reaches one of the six existing SQL execution
  methods keeps its source, property, and execution lines in CLI and MCP.
- **An MCP client asks before RepoPilot runs a configured check.** A check
  named in the MCP `verify` input runs only after a per-check form approval
  that shows the executable, exact arguments, and working directory. The
  executable and configuration are rechecked before launch. CLI `--verify` is
  unchanged.
- **Fresher and quieter results.**
  - Creating, editing, or deleting `tsconfig.json` or `jsconfig.json` updates
    resolved imports within one MCP session, and a config-only alias change
    rebuilds cached relationships instead of keeping old edges.
  - A Markdown document such as an agent `SKILL.md` no longer reads as an
    access-control or request boundary because of words in its path.

## Compatibility

- **MCP verification needs an Elicitation-capable client.** In 0.24, a check
  named in the MCP `verify` input ran without asking. In 0.25 it runs only for
  a client that negotiated protocol `2025-11-25` and declared
  `elicitation.form`, after the user approves that check. Other clients still
  get the full static review, and each selected check is reported as skipped.
  Exact arguments are sent to the MCP client: keep secrets out of program and
  argument fields.
- Report schema stays `0.26`. The scan cache (schema 12) and parsed-facts
  cache (schema 10) are rebuilt once after upgrading.
- Plugin and Gemini extension version 0.25.0 work with CLI 0.24.0 or newer;
  the new review signals need CLI 0.25.0.

## Upgrade

```bash
cargo install repopilot --version 0.25.0 --force
npm install -g repopilot@0.25.0
```

Claude Code: `claude plugin marketplace update repopilot`, then
`claude plugin update repopilot@repopilot`. Codex:
`codex plugin marketplace upgrade`. Gemini CLI:
`gemini extensions update repopilot`.

## Evidence and limits

New detectors are verified with synthetic safe and unsafe fixtures, CLI/MCP
parity, and cached-versus-uncached parity. None has independently labeled
real-repository precision yet. Elicitation consent has not been exercised in a
released MCP client UI. See the
[0.25 evidence ledger](../engineering/v0.25-evidence-ledger.md).
