---
title: Faster reviews on large repositories, and findings that hold with or without the cache
description: RepoPilot 0.24.3 reviews a change in a large repository about four times faster with the same findings, makes cached and uncached reviews agree, detects generated code and entry points from headers and top-level definitions only, and drops two removal false alarms.
---

## Highlights

- **Reviews on large repositories are about four times faster.** On next.js
  (34k files), a review of a one-file change takes ~8.5 s instead of ~32 s
  once the first review has built the cache (~15 s), and a full strict scan
  15 s instead of 35 s, with identical findings.
  - Two graph checks compared every unresolved import with every file; both
    use an index now.
  - A change that touches only tests reuses the cached repository context
    instead of rebuilding it on every review.
- **Cached and uncached reviews agree.** The repository-context cache dropped
  three file facts, so every Rust module with inline tests read as
  `source-without-test` on a cached review. The same change now gets the same
  findings either way.
- **Generated code and entry points are recognized from structure.**
  - A generated-code marker counts in a comment in the first 40 lines, and it
    is read once with the file. A full scan audited `@generated` files as
    hand-written code, while marker words deep in a file hid hand-written
    files from every audit (cobra's `command.go`, ripgrep's `literal.rs`).
  - An entry function counts as a top-level definition (`fn main(`,
    `func main(`, `if __name__ == "__main__"`), not as the same words in a
    test string.
- **Two removal false alarms are gone.** Deleting a test file whose tests all
  moved to another file is a move, and a renamed test that dropped a check is
  reported as `assertions removed` with both names.
- **A review reports framework rules for the changed files**, like every other
  per-file rule. A full scan still reports them for every file.

## Compatibility

No breaking changes. Report schema stays `0.26`. The scan cache (schema 9) and
repository-context cache (schema 10) are rebuilt once after upgrading. A full
scan can report more findings than 0.24.2 in files that were wrongly treated as
generated, and fewer in files that are generated. Plugin and Gemini extension
version 0.24.3 works with CLI 0.24.0 or newer.

## Upgrade

```bash
cargo install repopilot --version 0.24.3 --force
npm install -g repopilot@0.24.3
```

Claude Code: `claude plugin marketplace update repopilot`, then
`claude plugin update repopilot@repopilot`. Codex:
`codex plugin marketplace upgrade`. Gemini CLI:
`gemini extensions update repopilot`.
