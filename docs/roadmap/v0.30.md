# v0.30 — Semantic Change Intelligence

Status: planned; development continues on `feat/v0.29` after the reliability
foundation. Scope is conditional on measured v0.29 baselines. Prefer a small
end-to-end TypeScript/JavaScript pilot over a universal engine rewrite.

| ID | Outcome | Acceptance |
|---|---|---|
| RP30-01 | Symbol index | Stable declaration/reference identity, lexical scopes, local unique resolution, explicit ambiguous/unresolved results. Reuse existing frontend and resolver facts. |
| RP30-02 | Semantic facts / bounded IR | Versioned assignments, calls, branches, returns and source ranges; unsupported constructs recorded, deterministic cache serialization. |
| RP30-03 | Control-flow pilot | Basic blocks and edges for supported if/else, returns and straight-line code; unreachable assertions and guard dominance with safe controls. No unsupported CFG inference. |
| RP30-04 | Local cross-file summaries | Uniquely resolved direct calls across files, bounded depth and work; report source, declaration and sink; abstain on recursion/dynamic calls. |
| RP30-05 | Semantic test integrity | Prioritize assertion trivialization, test discovery and unreachable/async checks using real motivating changes; audit existing recognizers before adding rules. |
| RP30-06 | Symbol-level impact | Link changed declarations to proven local uses; retain file-level graph fallback and explicit coverage. |
| RP30-07 | Contract deltas | Compare supported before/after semantics; distinguish coordinated changes, unresolved calls and broken local contracts. |
| RP30-08 | Proof capability coverage | Per-family assessed/limited/unavailable status with reasons; preserve existing report readers and CLI/MCP parity. |
| RP30-09 | Release evaluation | Repeat frozen benchmark, report per-family metrics, latency, memory and unsupported cases. No claim of compiler-equivalent or whole-program analysis. |

No release claim follows solely from fixture success. Keep deterministic offline
analysis, evidence-backed defaults, and existing security boundaries. Each
workstream requires unsafe, safe, ambiguity and false-negative regression
controls where applicable. Reassess scope after baseline measurements.
