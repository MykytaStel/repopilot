## RP30-01 first slice: observed module-surface index

The experimental `analysis::semantic::SymbolIndex` exposes a deterministic
in-memory projection for JS/TS. It consumes existing parsed symbol facts
through `from_scan_facts`, or uses the shared parse frontend through
`from_sources` for explicitly supplied source. It does not reread source
when existing facts are unavailable. The default CLI, MCP, ChangeProof,
scan output and cache schema remain unchanged.

The snapshot-local identity includes repository-relative path, observed
export name, syntactic namespace and line span. Import references retain
original specifier, local alias, import name, line and byte range. A unique
observed export is not proof of its owning declaration. Multiple observed
file candidates or export occurrences are ambiguous. Forwarded/wildcard
exports, missing inventory entries, mixed type/value namespaces, unsupported
specifiers and incomplete facts remain explicitly unresolved. Resolution is
conditional on the supplied inventory and the existing relative-module
candidate model, not compiler-equivalent module resolution. Extensionless
and package/alias imports are not supported by this first bounded path.
Parse failures and unsupported files remain visible in module coverage.

No claim of complete symbol coverage: the inherited extractor does not
enumerate every declaration, reference or export form. Lexical scope,
shadowing, stable cross-revision identity, call-site resolution, type
resolution, barrel tracing and integration into review are still open.
The next slice should introduce bounded lexical declaration/reference
facts for a supported straight-line subset and abstain on unsupported
scope constructs. Do not enable blocking findings based on this pilot.

Tests: named/default/type imports, aliases, duplicate observed exports,
ambiguous module candidates, missing or malformed sources, wildcard
forwarding, deterministic serialization and cached/source parity.
Run `cargo test --lib analysis::semantic::` before expanding the pilot.
