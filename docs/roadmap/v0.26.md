# v0.26 — first-use clarity, actionability, and measured performance

Status: implementation in progress. Package version remains `0.25.0` until
release preparation. The JSON report schema remains `0.26` and is a separate
contract.

The owner selected a balanced scope and explicitly directed the work to
proceed without independent observers or testers. This permits the planned
technical work; it does not claim independent first-use, production accuracy,
adoption, or usefulness evidence.

See the approved [design](../engineering/v0.26-design.md), its
[performance baseline](../engineering/v0.26-performance-baseline.md), and the
[evidence ledger](../engineering/v0.26-evidence-ledger.md).

## Approved scope

### RP26-01 — Improve setup-to-review guidance

- Carry a custom `init --path` config into the printed first-review command.
- Label current-change review separately from a repository-wide scan.
- Omit already configured verification IDs from exported suggestions and name
  the omitted IDs in console output.
- Keep `init` usable when an existing config cannot be parsed; show every
  candidate and disclose that comparison was unavailable.
- Keep suggestions inert and separate from active config. Preserve `--force`
  and file ownership behavior.

### RP26-02 — Keep one primary review action

- Retain the canonical decision header and its single `Next action`.
- Make the trailing console block a secondary `Details` hint for `--detail full`.
- Preserve report meaning, detector behavior, gates, JSON, SARIF, and MCP.

### RP26-03 — Reduce measured cache cost

- Stream JSON cache reads and writes through buffered I/O.
- Serialize borrowed cache entries in deterministic map order without cloning
  every payload.
- Preserve cache fields, schema versions, invalidation, and backup recovery.
- Keep the change only if comparable same-host timing or RSS improves and no
  existing performance budget regresses.

### RP26-04 — Stop configured-check process trees reliably

- On Unix, keep each configured check in its own process group and terminate
  that group on timeout or cancellation.
- On Windows, create the configured process suspended, attach it to a
  kill-on-close Job Object, start output readers, then resume the process.
- Verify on both platforms that a timed-out or cancelled check leaves no
  running child process.
- Preserve the configured command, host-permission boundary, and structured
  verification outcomes.

## Explicitly deferred

- Do not add or restore a `doctor` command.
- Do not add detector families, widen language/syntax coverage, or change signal
  confidence, severity, or gate eligibility without concrete evidence and a
  safe control.
- Do not close the independent first-use or production detector evidence rows
  with maintainer-run fixtures, scans, or benchmarks.

## Release acceptance

- The four technical slices above have fixture/build evidence and are recorded
  separately from independent user or accuracy evidence.
- Same-host before/after results use the same workloads and stay within existing
  performance budgets; unsupported claims and unchanged metrics are disclosed.
- Configured-check timeout and cancellation scenarios confirm process-tree
  cleanup on Unix and Windows CI.
- Local Rust formatting/build and the repository's release handoff requirements
  are recorded accurately. Human testers and independent observers are not part
  of this owner-directed slice.
- User-facing changes appear in the unreleased changelog and final release notes.
- No package-version, release-tag, publication, or merge claim is made until its
  separate release steps are performed.
