## Re-scope (2026-09-30)

The first 0.24 plan, _Calibrated Trust_, shipped its release pipeline, risk
calibration, and explained-proof work on `main` (Phases 0, A, and B below).
That work stays in this release.

Its remaining phases — deeper public-API contracts and broader rule evidence —
move to the 0.25 backlog (RP24-010…014). They deepen a review experience that
too few people have tried yet. Local, deterministic review of Git changes is
now a claim several static-analysis vendors and open-source review tools make
with far larger reach, so repeating it does not tell a new user why to install
RepoPilot.

0.24 instead adds one capability that has no established tool and fits in one
sentence: **RepoPilot tells you when a change turned CI green by weakening the
checks that judge it.**

## What 0.24 Is Responsible For

1. **Honest green.** `review` reports when a change weakens its own checks:
   tests skipped or focused, test cases or assertions removed, suppressions
   added (including suppressions of RepoPilot itself), and CI or
   test-runner gates relaxed. Each signal names the file, the line, and the
   before/after count.
2. **The same evidence for any author.** The signals read the Git change, not
   its author. A developer reviewing a teammate's PR and a coding-agent session
   get identical evidence.
3. **Measured on real changes.** A labeled corpus of public pull requests,
   human- and agent-authored, states how often each kind of weakening occurs
   and what RepoPilot catches, with denominators, marked exploratory.
4. **In the loop where changes are made.** Optional integrations run the same
   check before a change reaches review: an exact snapshot baseline, a stop-hook
   gate for coding agents, a pre-commit hook, and a CI preset.
5. **Calibrated, explained, rehearsed.** Already on `main`: severity-capped
   priority (`risk-v4`), named coverage limits, grouped proof obligations,
   2.7× faster large-diff review, and a release-candidate rehearsal path.

## Visible Difference From 0.23

| 0.23 | 0.24 |
|---|---|
| Test removal is reported only when a whole test file is deleted or emptied | Per-file test count, renamed or substituted tests, and per-test assertion count are compared before/after |
| A skipped, focused, or suppressed check is ordinary changed code | Named `test integrity` signals with file, line, and before/after counts |
| CI workflow and test-config edits are reviewed only as delivery-surface changes | Relaxed gates (removed step, `continue-on-error`, lowered coverage threshold, new ignore patterns, disabled strict mode) are named |
| Snapshot baseline is `HEAD` + dirty flag | Snapshot records the exact working tree, so pre-existing edits are not attributed to the session |
| No measured claim about real changes | A generated corpus report with prevalence and catch rate per signal, labeled exploratory |
| Priority is a score threshold | Priority is capped by severity (`risk-v4`, shipped) |
| `(limited)` without a cause; obligations listed one by one | Named limits and grouped obligations (shipped) |

## Release Principles

- Keep 0.23's contract: local-only, deterministic, no source upload, no
  implicit command execution, no new top-level command.
- **One lane.** 0.24 adds only capability that answers "did this change weaken
  what judges it?" A feature that does not answer that question waits for
  0.25, however useful it looks.
- **Structure over text.** Every integrity signal comes from syntax trees or
  parsed configuration, never from a substring match. A `skip` inside a string,
  a comment, or a test moved to another file is not a signal.
- **Precision before breadth.** A signal enters the `definitely` tier only when
  it has no benign reading without an explanation (a committed focused test, a
  deleted test file). Everything else is `probable` or advisory until the
  corpus says otherwise.
- Treat every exit-code change as a compatibility event: CHANGELOG note,
  migration guidance, and a fixture pinning the new behavior.
- Evidence tooling serves ledger rows; cap it at roughly one fifth of the
  release effort. Phase D reuses the zoo tooling and adds no new harness.
- Every PR updates its ledger row; the roadmap changes only when scope does.

## Phase C — Test and Gate Integrity Signals

Report changes that weaken the checks judging them. Signals join the existing
review tiers under a `test integrity` group and carry stable reason codes in
JSON, SARIF, MCP, and the Action.

Deliverables:

- **C1 Disabled or focused tests.** Added skip, `xfail`, ignore, or disabled
  markers and focused tests (`.only`, `fit`, `fdescribe`) in changed test code.
  A committed focused test silently disables the rest of the suite and is
  `definitely`; a skip is `probable` and shows its reason string when present.
- **C2 Test-level accounting.** A decrease in a test file's case count (not
  only to zero), a named test that disappears while another appears
  (substitution), a decrease in a test's assertion count, and an assertion
  replaced by a constant-true form. Tests moved between files in the same
  change are matched and not reported.
- **C3 Expectation rewritten with the code — dropped (2026-10-01).** The
  corpus (Phase D) found an expected value rewritten together with the code it
  checks in 19% of agent and 27% of human pull requests, every one a deliberate
  change of behavior. An advisory signal would fire on a quarter of changes and
  inform no decision. Revisit with data from agent sessions, not merged PRs.
- **C4 Suppressions added.** `@ts-ignore`, `@ts-expect-error`,
  `eslint-disable*`, `# noqa`, `# type: ignore`, `# pragma: no cover`,
  `#[allow(...)]`, `//nolint`, counted per file before and after, from comment
  and attribute nodes.
- **C6 Suppressions of RepoPilot itself.** Entries a change adds to
  `.repopilot/overlay.toml` are reported with what they suppress, their scope,
  and their reason; `.repopilot/` is otherwise excluded from the changed files,
  so an acknowledgement — or an agent silencing its own review — was invisible.
- **C5 Gates relaxed.** In CI workflows: a removed step, `continue-on-error`,
  `|| true`, or an always-false `if`. In test and type configuration: a lowered
  coverage threshold, new ignore/exclude patterns, `--passWithNoTests`,
  deselected tests, and strict type settings turned off.
- **Coverage.** Test code: TypeScript/JavaScript (Jest, Vitest, Mocha), Python
  (pytest, unittest), Go (`testing`), Rust (`#[test]`). Configuration: GitHub
  Actions, GitLab CI, `package.json`, Jest/Vitest config, `pyproject.toml`,
  `tsconfig.json`, mypy config. Java, Kotlin, and C# test frameworks follow in
  0.25 with zoo evidence.
- **Proof.** A `definitely` integrity signal keeps the decision at `REVIEW`
  until acknowledged in the repository's RepoPilot policy; a change to that
  acknowledgement is itself an integrity signal.

Definition of done:

- every signal kind has an unsafe fixture and a near-identical safe guard
  (marker in a string or comment, test moved to another file, assertion
  extracted into a helper, suppression removed rather than added);
- review of the zoo's pinned revisions adds no default-visible scan finding
  (integrity signals are review-only);
- integrity analysis adds at most 10% to the review median in the performance
  budget;
- the `--fail-on-review definitely` behavior change is pinned by a fixture and
  described in the CHANGELOG.

## Phase D — Integrity Corpus and Measurement

Measure the question 0.24 answers, on real changes, with its limits stated.
Replaces the broad rule-evidence phase of the first plan.

Deliverables:

- **Corpus.** About 200 public pull requests that modify test code, at pinned
  revisions: roughly half from coding-agent accounts or markers, half
  human-authored, plus reproductions of published test-weakening examples.
  Manifest and labels live in the repository next to the zoo expectations.
- **Labels.** Single-expert, blinded to RepoPilot output, per weakening kind,
  labeled `single-expert, exploratory`.
- **Baseline first.** Label and measure before most of Phase C is built; the
  prevalence per kind decides which C signals come first and whether release
  notes describe the problem as agent-specific or general.
- **Baseline result (2026-10-01).** 198 merged, approved pull requests from 62
  repositories (84 agent, 114 human). Unexplained weakening: 1 of 84 agent
  PRs (1.2%, 95% CI 0.2–6.4%), 0 of 114 human PRs. Weakening kinds with a stated
  or evident reason were common (25% agent, 39% human). Consequences: release
  notes describe integrity signals as making weakened checks visible for any
  author and make no claim that agents weaken tests more often; C3 is dropped;
  the next measurement samples agent PRs closed without merge, where review
  may have filtered weakening out.
- **Held-out and closed results (2026-10-01).** A held-out sample of 98 merged
  PRs (2026-03..05) was labeled blind after the detectors were tuned, and
  evaluated once. So were 62 agent PRs closed without merge. Unexplained
  weakening: 0 of 42 agent and 3 of 56 human held-out PRs, and 2 of 62 closed
  agent PRs (3.2%, 95% CI 0.9–11.0%). Neither result supports an
  agent-specific claim. Held-out precision:
  - `integrity.suppression-added`: 5/6, or 6/6 with one recorded
    reconciliation;
  - `integrity.gate-relaxed`: 1/1;
  - `integrity.assertions-removed`: 2/3;
  - test removal, integrity and whole-file signals combined: 5/8.

  Misses, listed as limitations:
  - checks trivialized by structure;
  - loosened matchers;
  - helpers in other files;
  - ESLint bulk suppression files;
  - module-level conditional skips;
  - Ginkgo specs.
- **Maintainer review (2026-10-02).** The maintainer reviewed all 6
  `weakened` verdicts and changed 3 to `justified`, because the labeler had
  not read the PR descriptions. Claude re-read 56 more labels against their PR
  descriptions, and none changed. Unexplained weakening after review:
  - merged agent PRs: 0 of 84 and 0 of 42;
  - merged human PRs: 0 of 114 and 2 of 56;
  - closed agent PRs: 1 of 62. The one closed case came from an agent PR that
    rewrote a test into one that no longer calls the method under test.

  Precision tables are unchanged, because kinds were not changed.
- **Report.** Generated: prevalence per kind and author group, and per-signal
  catches and false positives, with denominators and Wilson intervals.

Definition of done:

- the report regenerates from the committed manifest and labels;
- every quantitative claim in the README and release notes cites it;
- any false positive found is fixed or documented as a limitation.

## Phase E — Agent and CI Integration

These integrations are optional. They serve a developer who wants a coding
agent, a commit hook, or CI to run the same integrity check before a human
reviews the change; `repopilot review` stays the core workflow for any change.

Deliverables:

- **Exact snapshot baseline.** `snapshot` records the working tree as a commit
  object without touching the index or worktree, so edits that predate a
  session are not attributed to it. Older snapshot files stay readable.
- **Stop-hook gate.** A guardrail recipe and packaged plugin for Claude Code
  (hook, MCP configuration, and instructions) and a Cursor hook recipe. Exits
  non-zero only for `definitely` integrity or security signals, with a message
  sized for agent context: file, line, and what to restore.
- **Commit and CI.** A pre-commit hook and a GitHub Action preset whose PR
  summary lists the integrity group first.
- **MCP parity.** `repopilot_review_change` returns integrity signals with the
  same reason codes and verdict as CLI JSON.
- **Latency.** Review of a change of up to 20 files stays under 1 s median in
  the performance matrix.

Definition of done:

- a scripted coding-agent session that skips a failing test and deletes an
  assertion is blocked by the stop hook with a machine-readable reason, and
  restoring both clears it;
- MCP and CLI JSON agree on verdict, reasons, and integrity signals.

## Compatibility Contract

- No top-level command is added or removed; existing flags keep their meaning.
- Two intended behavior changes, each with a CHANGELOG migration note and a
  pinning fixture: priority is `risk-v4` (shipped), and `--fail-on-review
  definitely` can now fail on a `definitely` integrity signal.
- Report schema changes stay additive (new signal kinds and reason codes); a
  schema bump is made only if a field's meaning changes.
- Snapshot files written by 0.23 remain readable; their review states that the
  baseline is `HEAD` plus a dirty flag.

## Non-Goals

RepoPilot 0.24 does not add:

- hosted services, telemetry, source upload, or an embedded LLM;
- autofix, automatic revert, or implicit command execution;
- claims about who authored a change;
- detection of hard-coded or special-cased return values — that needs
  semantics beyond structural evidence;
- deeper public-API contracts or broad rule evidence (0.25 backlog,
  RP24-010…014);
- new languages, or evaluation harnesses that do not close a ledger row.
